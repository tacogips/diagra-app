## Intent

AI-ready documentation: how BPMN elements are stored in JSONL, the lint
rules, the CLI commands, an original guideline file users can drop into
`.claude/rules/` for AI review, and the original purchase-request example
document.

## Non-goals

- No code changes. No text, labels or structure copied from the article
  or `.reference/` (paraphrasing the article is also out: write original
  guidance).
- No marketing claims about bpmn.io compatibility beyond what the tests
  prove (import/export round trip, opening in bpmn.io is a design goal:
  phrase it as "BPMN 2.0 XML with the standard namespaces").

## File-level changes

- `README.md`: add a "BPMN operation flows" section after "Sequence
  authoring" (README.md:281) covering: the `bpmn` page kind and "Add BPMN
  page", the BPMN palette, connection rules (the four acceptance rules and
  auto-correction), the problems panel, `.bpmn` open/import/export in the
  desktop, and links to `docs/bpmn/*.md`. In the "Command line" section
  (README.md:94) add example lines for `diagra-cli lint` and
  `diagra-cli bpmn import|export` with their exit codes (0 clean, 1 error
  findings or `--check` drift, 2 usage/parse/config error, 3 `--strict`
  warnings), matching the bpmn-12 `USAGE` text and design section 8.
- `docs/bpmn/format.md`: every `bpmn.*` type of design 3.2 with its
  semantic fields and one sample JSONL element record per type (original
  ids such as `task-review`), `parent` membership rules,
  `EventDefinition`, `isDefault`, `visual.labelBounds`, and the
  `extensions.bpmnXml` interchange metadata (design 3.4). State that
  coordinates and style live in `visual` and semantics in `semantic`, so
  an AI can read and diff the semantic part.
- `docs/bpmn/lint-rules.md`: a table of all 23 rule ids with recommended
  severity and an original one-line description (consistent with
  `bpmnLintRuleDescription` from bpmn-05); a `.bpmnlintrc` example
  (`extends` plus per-rule overrides); config discovery (`--config`, then
  `.bpmnlintrc` in the working directory, else recommended); note that the
  desktop always uses recommended; note intentional divergences (design
  13).
- `docs/bpmn/ai-review-rules.md`: an original example guideline for
  `.claude/rules/`: conformance target (Descriptive palette, Analytic
  constructs allowed), task granularity (one actor, one verb-object
  action), labelling rules (verb-object tasks, question-form gateways,
  YES/NO outgoing labels, message throw labels in "send" form and catch
  labels in "receive" form, matching throw/catch pairs), one lane per
  role, and a review checklist that pairs semantic checks with
  `diagra-cli lint` in CI.
- `docs/bpmn/purchase-request.jsonl`: byte-identical copy of
  `packages/io/src/__fixtures__/bpmn/purchase-request.jsonl` (generated by
  bpmn-06). Copy with `cp`; never hand-edit.
- `packages/io/README.md`: a short "BPMN 2.0 XML" note: `importBpmnXml`,
  `exportBpmnXml`, `bpmnSemanticProjection`, no XML dependency, DOCTYPE
  rejected, unsupported content preserved with warnings.

## Pitfalls

- ASCII only, no emojis.
- Every CLI example must actually run with the implemented commands (run
  them; see verification).
- Do not document features that do not exist (no desktop lint config, no
  vertical pools, no PNG/PDF).
